# Engineering Codex

## Purpose

Engineering Codex is the operating system for my engineering life.

It is not just notes. It is the place where learning, projects, research, portfolio work, and AI-assisted workflows become one coherent system.

The Codex itself is Project 0.

## Mission

Become an AI-amplified systems engineer who can design, build, debug, automate, and understand systems across the full stack, from hardware to AI infrastructure.

The goal is mastery of systems, not memorization of technologies.

## Core Philosophy

The Codex should answer, quickly and consistently:

- What am I working on?
- Why does it matter?
- What project does it support?
- What is the next action?
- What is blocked?
- How does this help my long-term mission?

If it cannot answer those questions, the system should be improved.

## Principles

- Build systems, not isolated skills.
- Every project should teach multiple disciplines.
- Every lesson should produce a reusable artifact.
- Every completed project should make future work easier.
- AI is an engineering multiplier, not a replacement.
- Documentation is part of engineering, not an afterthought.
- Avoid complexity unless it has measurable value.

## Recursive Principle

Engineering Codex is itself an engineering project.

It should use its own standards, document its own evolution, and improve itself over time through automation and AI assistance.

The point is to build a system that compounds knowledge.

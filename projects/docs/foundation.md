# Engineering Codex - Vision and Architecture

## Purpose

Engineering Codex is not a collection of notes.

It is a long-term Engineering Operating System (EOS) that will organize my learning, projects, career progression, documentation, portfolio, and AI-assisted workflows over the next decade.

The Codex itself is Project 0.

Everything else grows from it.

---

# Mission

Become an AI-amplified systems engineer capable of designing, building, debugging, automating, and understanding systems across the entire computing stack, from hardware to AI infrastructure.

The emphasis is on understanding systems, not memorizing technologies.

---

# Core Philosophy

The Codex exists to answer these questions every day:

* What am I working on?
* Why am I learning this?
* What project uses this knowledge?
* What is my next action?
* What is blocking me?
* How does this contribute to my long-term mission?

If the Codex cannot answer these questions quickly, it should be improved.

---

# The Golden Rule

**Don't learn technologies. Build systems.**

Every technology learned must eventually be used in a real project.

---

# Dogfooding Principle

Engineering Codex must follow the same engineering practices that it prescribes.

It is both:

* the operating system for my projects
* one of my projects

The Codex should continuously improve itself.

If a workflow is useful, document it.

If a workflow becomes painful, redesign it.

---

# Continuous Improvement Rule

Engineering Codex exists to make my life easier.

If maintaining it becomes busywork:

* simplify it
* automate it
* remove unnecessary parts

Never add complexity without measurable value.

# Engineering Principles

Always optimize for:

* understanding
* maintainability
* documentation
* automation
* reproducibility
* simplicity

Never optimize for appearing productive.

Optimize for becoming more capable.

---

# Definition of Learning

Watching videos is not learning.

Reading books is not learning.

Learning is demonstrated when I can:

* explain it
* build it
* debug it
* document it
* teach it
* reuse it

---

# AI Philosophy

AI is not the competition.

AI is the amplifier.

The objective is not to outperform AI.

The objective is to become an engineer who knows how to collaborate effectively with AI.

Every project should consider:

* where AI helps
* where engineering judgment is required
* where verification is essential

# Current Work Rules

Maximum Work In Progress (WIP):

* One primary project
* One learning track
* One maintenance task

Do not begin a new project before finishing or deliberately pausing another.

---

# Documentation Rule

Every meaningful piece of work produces at least one of:

* Documentation
* Source code
* Reusable script
* Experiment
* Architecture decision
* Lesson learned

Nothing valuable should remain only in memory.

---

# Success Metric

Success is not measured by the number of technologies learned.

Success is measured by:

* projects completed
* systems built
* knowledge retained
* documentation produced
* portfolio quality
* engineering judgment

---

# Recursive Principle

Engineering Codex is itself an engineering project.

It must use its own standards.

It must document its own evolution.

It should eventually become intelligent enough to help improve itself through automation and AI assistance.

---

# Initial Objective

Build a system that compounds knowledge.

Every lesson improves the Codex.

The improved Codex accelerates the next lesson.

Learning becomes a positive feedback loop rather than isolated experiences.

The Engineering Codex is not the destination.

It is the machine that continuously builds the engineer I want to become.
